Reusable solutions to common system design problems

What are System Design Patterns?

System Design Patterns are proven, reusable solutions to commonly occurring problems in distributed systems.

Client–Server Pattern

  • Client requests services from the server
  • Server processes requests and returns responses
  • Used in most web applications

Microservices Pattern

  • Application broken into small independent services
  • Each service owns its data
  • Improves scalability and maintainability

Monolithic Pattern

  • Single codebase and deployment unit
  • Easy to develop initially
  • Harder to scale as application grows

Event-Driven Architecture

  • Services communicate through events
  • Highly decoupled system
  • Used in real-time applications

CQRS (Command Query Responsibility Segregation)

  • Separate read and write operations
  • Improves performance and scalability
  • Common in high-load systems

Database per Service

  • Each service has its own database
  • Avoids tight coupling
  • Improves service autonomy
